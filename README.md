# Blocky Jump & Run (WebGL)

A side-view jump-and-run game that runs entirely in the browser with HTML5,
JavaScript and raw WebGL (no libraries, no build step).

- The world is generated procedurally, chunk by chunk, while the player moves.
- Enemies patrol back and forth on the platforms.
- Jump on an enemy from above to defeat it, touch it from the side and you lose a life.
- A two-layer city skyline with lit, blinking windows and distant hills moves
  behind the level with a parallax effect.
- Ground blocks are brick, floating platforms are wooden planks. Both material
  pictures are generated by an algorithm (wrapping noise + warped joint lines),
  every world seed paints its own colours and wobble, the joints sit on the
  same grid as the blocks and the picture repeats without any visible seam.
  Grass blades and occasional flowers line the walkable surface, and bushes,
  trees, flowers and street lamps decorate the platforms.
- Jet fighters cross the sky every few seconds and drop a bomb right over the
  player. The bomb hits the solid ground after 1.5 seconds and explodes there;
  the blast kills enemies and costs the player a life.
- The moon rises on the left in an arc, pauses at the top, and sets on the
  right: 10 s up, 3 s pause, 10 s down, then the cycle starts again.
- The moon is a real photo downloaded from the internet, used for one disc only.
  If the download fails, a drawn moon pattern is used instead, so the game also
  works offline. The level materials need no download at all.

## Run it

Option 1 - with a local web server (uses the ES modules in `src/`):

```bash
python3 -m http.server 8000
# open http://localhost:8000/index.html
```

Option 2 - a single self-contained file (works by double-clicking):

```bash
node tools/build-standalone.mjs
# open standalone.html in the browser
```

Chrome refuses ES module imports on `file://` URLs, hence the standalone build.

## Controls

| Key | Action |
|---|---|
| `A` / `D` or arrow keys | run left / right |
| `Space` or `W` or `Up` | jump (tap for a short hop, hold for a full jump) |
| `S` or `Down` | fast fall |
| `R` | generate a new world with a new seed |

The seed can also be fixed with `?seed=1234`.

## Tests

```bash
node --test tests/*.test.js
```

Covers the world generator, the physics (gravity, jumping, collision,
stomping), the camera maths, the moon arc, the jets, bombs and explosions, the
wrapping noise fields, the seamless material patterns, the anchored material
textures, the module graph of the standalone build and the constant names of
every module.

Three extra checks are worth running by hand as well:

```bash
node tools/build-standalone.mjs        # rebuild standalone.html
node tools/check-constants.mjs         # every constant name resolves
node tools/dump-textures.mjs           # material tiles as image files
```

The moon photo is fetched at runtime and never stored in the repository. The HUD
shows which textures were really downloaded. The two level materials are painted
into the pixel buffer instead of being loaded, because a photo of a real wall is
never tileable: its border does not match its own other side, so every repeat
shows a seam and cuts bricks in half.

## Browser verification

```bash
node tools/verify-browser.mjs          # 1200x720
WIDTH=1920 HEIGHT=1080 node tools/verify-browser.mjs
```

The script starts a local HTTP server and headless Chrome, presses WASD/Space
through the DevTools protocol, saves screenshots to
`/tmp/opencode/screenshots/` and checks that the canvas fills the window, that
WebGL draws geometry, that the player moves and is visible, that enemies patrol
and that stomping scores points. It also forces a jet to appear and captures the
falling bomb and the explosion.

## Structure

```
index.html            page, HUD and canvas

src/main.js           game loop: connects the modules, owns the run counters
src/world.js          procedural platforms, enemies, scenery, skyline data
src/physics.js        player movement, collision, enemy patrol
src/camera.js         camera follow, view size, world -> clip space
src/jets.js           jet fighters, falling bombs and explosions
src/moon.js           maths for the moon arc across the sky
src/textures.js       photo download + generated seamless materials
src/seamless.js       wrapping noise fields: tiles meet at the border
src/prng.js           seeded random generator and coordinate hash

src/renderer.js       WebGL context and the painting order of one frame
src/shaders.js        the two shader programs (flat colour, photo texture)
src/batch.js          the two quad batches: one draw call each per frame
src/painter.js        primitives: boxes, discs, photo boxes, sky gradient

src/drawSky.js        sky gradient, stars, drifting clouds, moon
src/drawCity.js       parallax skyline with lit windows, background hills
src/drawLevel.js      platform materials, grass, stone pillar, scenery props
src/drawActors.js     patrolling enemies and the player
src/drawThreats.js    jets, falling bombs and explosions

src/hud.js            HUD numbers, bomb warning, overlay, texture credits
src/input.js          keyboard state -> input object for the physics
src/debug.js          window.__game hooks used by the browser checks

tools/build-standalone.mjs   bundles src into standalone.html
tools/check-constants.mjs    finds constant names that resolve nowhere
tools/dump-textures.mjs      writes the material buffers as image files
tools/verify-browser.mjs     headless Chrome checks and screenshots
tests/                       node test suite
standalone.html              generated single-file version
```

Every visible box goes into one of two batches, so a frame costs at most two
`gl.drawArrays` calls. Magic numbers are avoided: colours, sizes, distances and
animation speeds are named constants in the module that uses them.
